## Invariants

- The intended project and loaded scene are proven before mutation or claims
- Licensed assets remain external and untracked
- Runtime truth is explicit and fixture data is never labeled live
- The first Play Mode frame reads as the Observatory
- The dashboard is fixed and only bounded internal windows scroll
- No player or replacement owner binary is built
- Tooling anomalies become durable issue evidence

## Risks

- Licensed prefab and material dependencies may not serialize portably into the tracked scene
- Live editor and MCP endpoint may drift between project instances
- The current camera and platform arrangement can expose large voids at wide aspect ratios
- Runtime contracts may not yet expose every desired governance, evidence, or communication field
- UI Toolkit scaling can become illegible or overlapping across target resolutions
- Visual tuning can mask runtime truth unless state labeling remains fail closed

## Stop Conditions

- The live Unity editor is attached to a different project than the intended FastWork Observatory
- MCP project identity cannot be proven or mutations target an ambiguous endpoint
- Unity reports compile errors that prevent safe scene mutation
- A required change would copy or publish licensed asset payloads
- Runtime communication requires an unsupported or secret-bearing direct AWS operation
- The work would need to absorb WP-14A or unrelated release-tail scope
